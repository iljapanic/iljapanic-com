# 02 — Better Auth magic-link login and protected /admin shell

- **Date**: 2026-09-02
- **Repo**: iljapanic-com
- **Lane**: factory
- **Blast radius**: new auth tables (Drizzle migration 0001), `lib/auth*.ts`, `/api/auth/*` route, new `app/admin/**` tree, three small admin components, Resend email helper, package.json deps.

All source paths are relative to the repository root. Depends on spec 01 being merged (Drizzle client at `db/index.ts`, schema at `db/schema.ts`, `runReadwiseSync` in `lib/readwise-sync.ts`).

## Goal and end use

A single administrator signs in at `/admin/login` by entering their email and clicking a magic link delivered by Resend. Only one email address (the `ADMIN_EMAIL` env var) can ever request a link or hold a session. Everything under `/admin` is protected. The first admin page is a small dashboard showing Readwise sync status with a "Run sync now" button; later specs add tools and books management on top of this shell.

## Decisions already made

- Library: `better-auth` (1.7.x) with its magic-link plugin, Drizzle adapter (`better-auth/adapters/drizzle`, provider `pg`), and `nextCookies()` plugin. No password auth, no OAuth, no other providers.
- Email: `resend` SDK, plain-text email containing the link. Sender from `RESEND_FROM_EMAIL`.
- Allow list: exactly one address from `ADMIN_EMAIL`, compared trimmed and lower-cased. Enforced in three places: before sending a link, before creating a user row, and when reading a session (`requireAdmin`).
- `BETTER_AUTH_URL` is NOT set; Better Auth infers the base URL from the request. Same `.env` locally and in production. `BETTER_AUTH_SECRET` is set.
- Routes: `/admin/login` (public), everything else under `/admin` protected. Auth API at the default `/api/auth/*`.
- Layout: `app/admin/**` is outside the `(main)` and `(plain)` groups and renders its own `SharedLayout` wrapper (the repo has no root `app/layout.tsx`).
- Protection: a `requireAdmin()` helper (server only) is called in the protected layout, in every protected page, and in every admin server action. No `proxy.ts`/middleware.
- UI: existing shadcn components in `components/ui` (`Button`, `Input`), Tailwind classes, sonner `toast` for feedback. Minimal, no new UI library.
- Package manager: Bun. Git: orchestrator commits; implementer never commits.

## Constraints (with the why)

- Fail fast: `ADMIN_EMAIL`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `BETTER_AUTH_SECRET` missing → throw with a message naming the variable, at the point of use inside handlers/actions (not at module scope in route files). — Silent defaults hide broken deploys; module-scope throws break `next build`.
- Non-allowed emails never receive an email and never get a user row. — Single-admin site; no enumeration protection needed beyond a generic UI message.
- Every protected page and server action calls `requireAdmin()` itself, even though the layout also does. — Layouts do not re-run on client-side navigation between sibling pages, and server actions bypass layouts entirely.
- Keep the existing code style (tabs, single quotes, no semicolons, `@/` imports). Do not run formatters repo-wide.
- Do not touch the Readwise sync internals; only call `runReadwiseSync('manual')`.

## Steps

0. From the repository root confirm `.env` defines `BETTER_AUTH_SECRET`, `ADMIN_EMAIL`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `DATABASE_URL` (names only). Confirm `drizzle/0000_*.sql` exists and the six `readwise_*` tables are present in the database (spec 01 applied).

1. `bun add better-auth resend` from the repository root.

2. `lib/email.ts`: `export async function sendEmail({ to, subject, text }: { to: string; subject: string; text: string })`. Reads `RESEND_API_KEY` and `RESEND_FROM_EMAIL` (throw if missing), `new Resend(key)`, `await resend.emails.send({ from, to, subject, text })`; if `error` is non-null throw `new Error(`Resend: ${error.message}`)`; return `data.id`.

3. `lib/admin.ts` (`import 'server-only'` is NOT available as a dependency; instead put a comment and never import it from client components):
   - `export function getAdminEmail(): string` — reads `ADMIN_EMAIL`, throws if missing, returns trimmed lower-cased.
   - `export function isAllowedEmail(email: string): boolean` — `email.trim().toLowerCase() === getAdminEmail()`.
   - `export async function requireAdmin()` — `const session = await auth.api.getSession({ headers: await headers() })`; if no session or `!isAllowedEmail(session.user.email)` → `redirect('/admin/login')` (from `next/navigation`); else return `session`.

4. `lib/auth.ts`:
   ```ts
   export const auth = betterAuth({
   	database: drizzleAdapter(db, { provider: 'pg' }),
   	emailAndPassword: { enabled: false },
   	databaseHooks: {
   		user: { create: { before: async (user) => { if (!isAllowedEmail(user.email)) throw new APIError('FORBIDDEN', { message: 'This email is not allowed' }); return { data: user } } } },
   	},
   	plugins: [
   		magicLink({
   			expiresIn: 60 * 15,
   			sendMagicLink: async ({ email, url }) => {
   				if (!isAllowedEmail(email)) { console.warn('magic link requested for non-admin email'); return }
   				await sendEmail({ to: email, subject: 'Sign in to iljapanic.com admin', text: `Sign in: ${url}\n\nThis link expires in 15 minutes.` })
   			},
   		}),
   		nextCookies(), // must be last
   	],
   })
   ```
   Imports: `betterAuth` from `better-auth`, `drizzleAdapter` from `better-auth/adapters/drizzle`, `magicLink` from `better-auth/plugins`, `nextCookies` from `better-auth/next-js`, `APIError` from `better-auth/api`, `db` from `@/db`. The `warn` must not include the email address.

5. `lib/auth-client.ts`: `createAuthClient({ plugins: [magicLinkClient()] })` from `better-auth/react` and `better-auth/client/plugins`; export `authClient`.

6. `app/api/auth/[...all]/route.ts`: `export const { GET, POST } = toNextJsHandler(auth)` from `better-auth/next-js`.

7. Auth schema: from the repository root run `bunx @better-auth/cli@latest generate --config lib/auth.ts --output db/auth-schema.ts` (answer yes to overwrite prompts; if the CLI cannot load the config because of the `@/` alias, temporarily run it with `--config` pointing at a copy using relative imports in the scratch area and copy the output in — the committed file must be `db/auth-schema.ts`). Then add `export * from './auth-schema'` to `db/schema.ts`, run `bun run db:generate` (produces `drizzle/0001_*.sql` with `user`, `session`, `account`, `verification` tables) and `bun run db:migrate`. This spec authorises both commands.

8. `app/admin/layout.tsx`: `export const metadata = { title: { default: 'Admin', template: '%s · Admin' }, robots: { index: false, follow: false } }`; renders `<SharedLayout><main className="container mx-auto max-w-3xl py-12">{children}</main></SharedLayout>`.

9. `app/admin/login/page.tsx` (server component): if a valid admin session already exists (`auth.api.getSession` + `isAllowedEmail`) → `redirect('/admin')`. Otherwise render a heading "Admin sign in" and `<LoginForm />`. Read `searchParams.error` (Promise in Next 16) and, if present, render a one-line muted error above the form ("That link is invalid or has expired.").

10. `components/admin/login-form.tsx`: email `Input` + `Button`. On submit `await authClient.signIn.magicLink({ email, callbackURL: '/admin', errorCallbackURL: '/admin/login?error=1' })`. Regardless of whether the address is allowed, on a non-error response show "If that address is allowed, a sign-in link is on its way." and disable the form. On `error` show `error.message` via `toast.error`.

11. `app/admin/(protected)/layout.tsx`: `await requireAdmin()`; render `<AdminNav email={session.user.email} />` then `{children}`.

12. `components/admin/admin-nav.tsx`: small top bar with "Admin" link to `/admin`, the email, and a "Sign out" `Button` calling `authClient.signOut()` then `router.push('/admin/login')` and `router.refresh()`.

13. `app/admin/(protected)/actions.ts` (`'use server'`): `export async function triggerReadwiseSync()` → `await requireAdmin()`, `const result = await runReadwiseSync('manual')`, `revalidatePath('/admin')`, return `{ ok: true, ...result }`; on error return `{ ok: false, message }` (do not leak stack traces).

14. `app/admin/(protected)/page.tsx`: `await requireAdmin()`; query `readwise_sync_runs` (last 5, newest first) and counts of books/highlights/tags with Drizzle; render a "Readwise" section: three counts, a table of runs (started, status, trigger, books, highlights, message), and `<SyncButton />`.

15. `components/admin/sync-button.tsx`: `Button` with `useTransition`; on click call `triggerReadwiseSync()`; toast success with `${bookCount} books, ${highlightCount} highlights` or error message; `router.refresh()` afterwards.

16. Delete `components/globals/admin-header.tsx`.

## Acceptance criteria

- `bunx tsc --noEmit` exits 0; `bun run lint` has no errors; `bun run build` exits 0 and lists `/admin`, `/admin/login`, `/api/auth/[...all]`.
- `ls drizzle/*.sql` lists exactly two files; the second contains `CREATE TABLE "user"`, `"session"`, `"account"`, `"verification"`.
- `grep -c "requireAdmin()" "app/admin/(protected)/layout.tsx" "app/admin/(protected)/page.tsx" "app/admin/(protected)/actions.ts"` reports ≥ 1 for each file.
- `test ! -f components/globals/admin-header.tsx`.
- `grep -rn "server-only" lib/admin.ts` prints nothing (package not installed); `grep -rn "from '@/lib/admin'" components/` prints nothing (never imported from client components).
- HTTP, with `bun run dev` running and `$ADMIN_EMAIL` taken from `.env` by a Bun script (never echoed):
  - `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/admin` prints `307` and the `location` header is `/admin/login`.
  - `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/admin/login` prints `200`.
  - `curl -s -X POST http://localhost:3000/api/auth/sign-in/magic-link -H 'content-type: application/json' -H 'origin: http://localhost:3000' -d '{"email":"nobody@example.com","callbackURL":"/admin"}'` returns 200 and afterwards `select count(*) from verification where identifier like '%nobody@example.com%'` is 0 (query via a short `bun -e` script using `db`).
  - The same POST with the admin email returns 200; the `verification` table gains one row; Resend returns an id (visible in server log line you add at `info` level WITHOUT the URL or email). The real admin inbox receives one email — acceptable and expected.
  - Read that row's token from the database (plain storage is the plugin default) and `curl -s -c cookies.txt -o /dev/null -w '%{http_code}' "http://localhost:3000/api/auth/magic-link/verify?token=<token>&callbackURL=/admin"` prints a 3xx to `/admin`; then `curl -s -b cookies.txt http://localhost:3000/admin` returns 200 and contains "Run sync now" and the admin email.
  - `curl -s -b cookies.txt -o /dev/null -w '%{http_code}' http://localhost:3000/admin/login` prints `307` (signed-in users are bounced to `/admin`).
  - Delete `cookies.txt` when done.

## Verification method

Tier: typecheck + lint + build, apply migration, then drive the magic-link flow over HTTP using the token read back from the database.

### Prerequisites
- Bun, Node ≥ 22, `.env` populated (see Step 0), spec 01 applied, network access to Resend and Neon.

### Targeted automated checks
- From the repository root: `bunx tsc --noEmit` → 0. Covers the auth instance and plugin types.
- From the repository root: `bun run build` → 0. Covers route registration and module-scope env safety.
- The HTTP sequence above. Covers redirect, allow list, verification, session cookie, dashboard render.

### Repository-wide checks
- `bun run lint` → 0 errors.

### Manual/browser verification
- Surface: `/admin/login`. Steps: enter the admin email, submit, open the emailed link, land on `/admin`, click "Run sync now", see the toast and the new run row, click "Sign out", get bounced to `/admin/login`. Evidence: screenshot or the curl transcript above. If Resend rejects the sender (unverified domain), report BLOCKED with the Resend error message.

### Portability confirmation
No planner paths, hosts, sessions, temp paths, or planner-only commands. Port 3000 is Next's documented default.
