# 01 — Drizzle foundation, Readwise sync overhaul, commonplace feed

- **Date**: 2026-09-02
- **Repo**: iljapanic-com
- **Lane**: factory
- **Blast radius**: database layer (Prisma → Drizzle), Readwise sync (lib + API routes + Vercel cron), commonplace server actions and the two commonplace client components, package.json scripts/deps, docs/readwise-sync-setup.md.

All source paths are relative to the repository root.

## Goal and end use

Replace Prisma with Drizzle ORM on a fresh Neon Postgres database, and rebuild the Readwise → commonplace pipeline so that a Vercel cron job runs once a day, fetches only the Readwise items tagged `@share`, reconciles them into the database (including removals), and the `/commonplace` page filters by tag correctly and efficiently. The database contains only Readwise data today, so there is no data migration: the new schema is created from scratch and populated by running the sync.

## Decisions already made

- Package manager: Bun (`bun install`, `bun run`, `bunx`).
- ORM: Drizzle ORM (`drizzle-orm` 0.45.x, `drizzle-kit` 0.31.x). Not Prisma. Prisma is removed entirely.
- Database: Neon Postgres. Driver: `@neondatabase/serverless` `Pool` with `drizzle-orm/neon-serverless` (WebSocket driver; supports interactive transactions). Do NOT use the neon-http driver (no transactions). Do NOT install `ws`: Node 22+ has a global `WebSocket` and the runtime here is Node 24 locally and Node 22+ on Vercel.
- Migrations: SQL files generated by `drizzle-kit generate` into `drizzle/` and committed. Applied with `drizzle-kit migrate`. Never `push` outside local experimentation.
- Readwise publish signal: a book (Readwise "user book") is published if and only if one of its book tags, case-insensitively, equals `@share`. Nothing else is fetched or stored.
- Readwise API: v2. Books via `GET https://readwise.io/api/v2/books/?page_size=1000` (follow `next` until null). Highlights via `GET https://readwise.io/api/v2/export/?ids=<comma separated user_book_ids>&includeDeleted=true` (follow `nextPageCursor` until null). Auth header `Authorization: Token <READWISE_ACCESS_TOKEN>`. Verified against the live account on 2026-09-02: 2172 books total, 77 tagged `@share`, 558 highlights across them; `export?ids=` returns `book_tags`, `highlights[]` with `is_deleted`/`is_discard` flags.
- Sync strategy: a full reconcile on every run (no incremental watermark). The shared set is small, so this is cheaper and self-healing: tag removals, deletions and edits all propagate.
- Schedule: Vercel cron, `0 0 * * *` (midnight UTC), Pro plan. Route `GET /api/cron/readwise-sync`, protected by `Authorization: Bearer <CRON_SECRET>`.
- Manual trigger stays at `POST /api/commonplace/sync`, protected by the single `API_KEY` env var. `COMMONPLACE_API_KEY` is retired; `/api/commonplace/shared` uses `API_KEY` too.
- Tags: stored once, normalized. `name` = trimmed, lower-cased, whitespace runs replaced by `-`. `label` = `name` with `-` replaced by spaces. `@share` is never stored as a tag (every stored book is shared by definition).
- Table names keep the `readwise_` prefix so later CMS tables (`books`, `tools`) do not collide.
- Environment: one set of credentials for local and production; `.env` is populated. `.env.example` already lists every variable and must stay in sync.
- Git: no branches. The orchestrator commits; the implementer never commits.

## Constraints (with the why)

- Fail fast on missing configuration: `DATABASE_URL`, `READWISE_ACCESS_TOKEN`, `API_KEY`, `CRON_SECRET` are read where needed and a missing value throws (or returns a 500 with an explicit message from a route handler). Never substitute a default. — Silent fallbacks hide broken deployments (user's global rule).
- No module-scope throws in route files that would run during `next build`. Validate env inside handlers or inside lazily called functions. — `next build` evaluates route modules; a throw there breaks the build rather than the request.
- Keep the client component `components/commonplace/commonplace-item.tsx` importable from the browser: `lib/readwise.ts` must not import Node-only or database modules. — It imports `getCategoryLabel` from there today.
- Match the existing code style: tabs, single quotes, no semicolons, `@/` imports. Do not run Prettier or ESLint `--fix` repo-wide. — Keep the diff reviewable.
- Do not over-engineer: no queues, no locks, no retries beyond the 429 handling described, no new abstractions beyond the files listed. — Personal site; boring code wins.
- Per-request query budget on `/commonplace`: `getCommonplaceData` ≤ 5 SQL statements, `getAvailableTags` ≤ 2, regardless of library size. — The old implementation loaded every shared book into memory on every request.

7. `lib/readwise-sync.ts` — `export async function runReadwiseSync(trigger: 'cron' | 'manual'): Promise<SyncResult>` where `SyncResult = { runId, bookCount, highlightCount, removedBookCount, durationMs }`:
   1. Read `READWISE_ACCESS_TOKEN`; throw if missing. Insert a `readwise_sync_runs` row with `status: 'running'` and the trigger; keep its id.
   2. `listBooks`. Filter to `shared = books.filter(b => b.tags.some(t => t.name.trim().toLowerCase() === '@share'))`.
   3. `exportBooks(sharedIds)`. Build the in-memory model: for each export book, `highlights = highlights.filter(h => !h.is_deleted && !h.is_discard)`; `tags` = normalised names excluding `@share` (dedupe after normalisation); each highlight's tags normalised the same way. `lastHighlightAt = max(highlight.highlighted_at)` or null; `highlightCount = highlights.length`. Also drop export books whose `is_deleted` is true.
   4. Slugs: `base = slugify(title).slice(0, 80)` (import `slugify` from `@/lib/utils`); if `base` is empty use `readwise-${readwiseId}`. Load existing `{ readwiseId, slug }` pairs from the DB. A book that already has a row keeps its existing slug. New books get `base`, unless `base` is already taken by another book (existing row or another new book in this batch), in which case `${base}-${readwiseId}`.
   5. In ONE `db.transaction`:
      - Delete from `readwise_books` where `readwise_id NOT IN (sharedIds)` (cascades). Count = `removedBookCount`. If `sharedIds` is empty, delete all rows.
      - Upsert all tags (`onConflictDoUpdate` on `name`, set `label`).
      - Upsert books on `readwise_id` (update every mutable column + `synced_at = now()`; keep `slug` as decided above).
      - For each book: upsert highlights on `readwise_id`; delete highlights of that book whose `readwise_id` is not in the incoming set; delete then re-insert `readwise_book_tags` for the book; delete then re-insert `readwise_highlight_tags` for its highlights. Use batched multi-row inserts (one insert statement per table per book at most, or per batch across books). No per-row awaits in a loop where a multi-row statement will do.
      - Delete tags that no longer have any book_tags or highlight_tags rows.
   6. Update the run row: `status: 'success'`, `finished_at`, counts, `message`. On any error: update the run row with `status: 'error'` and the error message, then rethrow.

## Verification method

Tier: typecheck + lint + production build, then apply the migration and drive the sync and the page over HTTP.

### Prerequisites

- Bun, Node ≥ 22.
- `.env` with `DATABASE_URL` (Neon), `READWISE_ACCESS_TOKEN`, `API_KEY`, `CRON_SECRET` populated. No values are printed anywhere.
- Network access to `readwise.io` and the Neon host.

### Targeted automated checks

- From the repository root: `bunx tsc --noEmit` → exit 0. Covers the Drizzle types and the new action contract compiling against the client components.
- From the repository root: `bun run lint` → 0 errors. Covers unused imports left by the rewrite.
- From the repository root: `bun run build` → exit 0, `/commonplace` and `/api/cron/readwise-sync` appear in the route list. Covers module-scope env throws that would break the build.
- From the repository root: the grep criteria above.

### Repository-wide checks

- `bun run build` (includes `contentlayer2 build`).

### Manual/browser verification

- Surface: `/commonplace` on the dev server after a successful sync. State: database populated by the manual sync. Steps: open the page, click a tag under a book; expected: the URL becomes `/commonplace?tags=<name>`, the list narrows, the chip for that tag appears active in the tag cloud, clicking the chip again clears it. Evidence: the curl checks above or a screenshot. Blocked behaviour: if the database is unreachable, report BLOCKED with the connection error.

### Portability confirmation

This spec contains no planner checkout path, hostname, browser session, VM URL, temporary path, undocumented port (3000 is Next's documented default), or planner-only command.
